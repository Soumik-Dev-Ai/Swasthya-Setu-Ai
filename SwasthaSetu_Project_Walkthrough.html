Swasthya Setu AI

Complete Regional Multilingual Support

Swasthya Setu AI is a comprehensive, AI-powered healthcare triage and financial navigation platform. It is designed to bridge the gap between rural/regional patients and critical healthcare infrastructure by combining state-of-the-art LLMs, real-time cost estimation, and local health worker (ASHA) integration.

1. Core Architecture

The platform is designed to be highly resilient, falling back gracefully when APIs fail or network connectivity drops.

Frontend (Vite + React + Tailwind)

  • Glassmorphism UI: A premium, dark-mode aesthetic utilizing deep blur effects, glowing cyan borders, and smooth framer-motion spring physics.
  • SearchSelect: Custom-built autocomplete comboboxes for all critical inputs (Cities, Hospitals, Diseases, Providers) for lightning-fast local filtering.
  • Zero-Dependency Mapping: Uses Pigeon Maps backed by OpenStreetMap (street tiles) and ArcGIS (satellite tiles) to provide interactive facility maps completely free of Google Maps billing dependencies.

Backend (FastAPI + Python)

  • Zero-Setup Database: Runs entirely on a local SQLite (swasthyasetu.db) file using aiosqlite for asynchronous performance. No heavy PostgreSQL or cloud database setup required for testing or local hosting.
  • Resilient AI Cascade: A sophisticated LLM routing system that attempts to use Gemini, but seamlessly falls back to Groq and NVIDIA if rate limits or failures occur.
  • Security & Rate Limiting: Enforced via slowapi to protect against DDoS and API spam.

2. Key Modules & Features

🚑 AI Symptom Triage (Vision + LLM)

Located in the Triage Tab, this is the first line of defense for a patient. - Multimodal Input: Patients can input text symptoms and optionally upload an image (e.g., a rash, wound, or scan). - Deterministic Safety Gate: The AI analyzes the inputs and runs them against a deterministic safety checklist (Red Flags) to immediately identify if the situation requires a 24/7 ER. - Severity Mapping: Classifies the case into Mild, Moderate, Severe, or Critical, and outputs matched potential conditions.

💰 Advanced Cost Estimation & Finance

Located in the Cost Estimate Tab, this module helps patients understand exactly how much a treatment will hurt them financially. - OSINT Cost Scraper (precision_service.py): Instead of hallucinating costs, the backend performs a lightweight OSINT web scrape against trusted medical authorities (NIH, Mayo Clinic) to fetch real-world data and inject it into the AI's cost models. - Financial Profiler: Patients input their monthly income, housing costs, EMIs, and food expenses. The engine calculates their true disposable income and cross-references it with the estimated hospital bills to warn them of potential financial ruin.

🛡️ Insurance Policy Checker

Located in the Insurance Tab, this tool prevents patients from being caught off guard by hidden hospital fees. - Dynamic Matching: Users select their insurance provider and plan. The system dynamically updates available plans based on the selected provider. - Gap Analysis: It calculates the expected treatment cost and subtracts the coverage limit, explicitly showing the patient their net out-of-pocket gap.

🏥 Facility Finder & 3D Maps

Located in the Facilities Tab, this module routes the patient to the right hospital. - Real-time Map: Plots verified hospitals on a satellite or street map. - Smart Filtering: Users can filter hospitals by ICU availability, PM-JAY Cashless support, 24/7 ER, and Blood Banks. - Cost Hyperlinking: Facilities feature a glowing net_expected_treatment_cost button that instantly bridges the user over to the Cost tab, autonomously pre-filling the target hospital and city.

🧑‍⚕️ ASHA Control Room

The Community Desk (ASHA Help Corner) bridges the AI with actual human healthcare workers on the ground. - Patient Registration: ASHA workers can log in via a secure PIN to access their control room. - Emergency Board: If a patient's Triage results trigger a Level-4 Critical alert, the case is immediately pushed to the local ASHA worker's emergency board. - Dispatch: The ASHA worker can accept the case, triggering an "En route" status to coordinate physical intervention.

3. Testing & Resilience Strategy

The system is fortified by an adversarial testing philosophy: - Fallback Supremacy: If the Python backend is completely offline, the React frontend catches the fetch failure and immediately falls back to a lightning-fast local mock engine to ensure the UI (like facility searching) never breaks. - API Torture Limits: The LLM cascade is designed to withstand API timeouts by failing over to secondary providers in milliseconds. - Strict Pydantic Validation: All JSON output from the AI models is aggressively sanitized and validated by Pydantic schemas to ensure malformed AI hallucinations can never crash the UI.
